**Audited:** 2026-11-21 · **Commit:** `ea70ed3` (local; production runs `f041684`, Fly v37)
**Method:** nine read-only auditors, one per slice, then a consolidation pass. Claims marked

## State of the branch

Everything marked ☑ is implemented on the local branch `audit-2026-11`, uncommitted. Verified on
the combined tree: `pnpm run lint`, `pnpm run check`, `pnpm run cf:check`, the unit suite, a
production build, and the e2e suite against the built server with outbound network blocked.

The Docker image was built locally and booted with networking disabled: it refuses to start
without `DATABASE_URL`, serves `/api/health`, answers 403 on `/admin` and `/%61dmin`, keeps the
host redirect on the canonical origin, ships all 33 font files its CSS references, holds only the
four runtime dependencies (no pnpm, no bundler), and closes the database on `SIGTERM`. It still
runs as root (DECIDE-7).

Not verified anywhere yet: the deploy script end to end, the Worker on Cloudflare, real
screen-reader output, and browsers other than Chromium.

### Before deploying this branch

1. **OWNER-1 first.** The rewritten privacy page says there are no third-party analytics; that is
   false while Cloudflare's beacon is injected.
2. **Snapshot the volume.** Migration `0009` (an index on `players.team_id`) makes this a migrating
   deploy — see `docs/restore.md`.
3. **Expect, once:** existing `/admin` sessions are invalidated (the session key is now derived),
   IPv6 visitors get new daily hashes (keyed on the /64), and error rows whose messages contain
   URLs start new fingerprints.
4. **Check afterwards:** `numbrrs.fly.dev/admin` and `/%61dmin` return 403; the dashboard's
   unique-visitor count still looks like distinct people (client IP is now trusted from Cloudflare
   only when the request host is `numbrrs.app`); a cache HIT still carries `max-age=0` once
   OWNER-2 and the Worker deploy are done.
5. **`pnpm run cf:deploy`** for the Worker changes, then purge the Cloudflare cache.

IDOR on user-owned rows, Tigris and account deletion have nothing to audit. Nothing score-like
is stored or ranked server-side, so "the client reports its own score" does not apply.
